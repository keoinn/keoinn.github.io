實驗 7：AI 協助自動化測試與 Markdown 測試報告生成

Wayne Chang

發表於：2026年10月16日

更新於：2026年10月17日

切記 AI Vibe Coding 的黃金準則：「工程師的價值在於定義規格與設計測試矩陣（Test Matrix），絕不盲信 AI 生成的程式碼！」

在前面的實驗中，我們已經在 app.py 實作了商品資源模組（/api/items），涵蓋了 Path Parameters、Query Parameters 與 Request Body 三大傳參途徑與邊界檢查。在專業的工程交付中，我們不會手動一個個去敲終端機驗收，而是引導 AI 為我們撰寫自動化測試腳本，並一鍵產出交付給團隊的 API 測試驗收報告。

1. 實驗步驟

第 1/6 步： 定義 API 測試矩陣（Test Matrix）規格

在請 AI 寫測試腳本前，我們先以架構師視角擬定今日的 8 大驗收測試情境：

編號測試案例名稱傳參途徑HTTP Method 與 URI / Payload預期狀態碼邊界與驗收重點
TC-01健康檢查端點-GET /api/health200驗證服務運行狀態
TC-02查詢單一商品PathGET /api/items/101200驗證 URL Converter 自動轉型整數
TC-03查詢不存在商品PathGET /api/items/999404驗證找不到資源時回傳 404 Not Found
TC-04複合條件查詢QueryGET /api/items?category=electronics&in_stock=true&sort=price_asc200驗證多條件組合過濾與升冪排序
TC-05非法型別防呆QueryGET /api/items?min_price=cheap400驗證將非數字傳入整數欄位時攔截回傳 400
TC-06區間邏輯防呆QueryGET /api/items?min_price=5000&max_price=1000400驗證 min > max 邏輯矛盾時攔截回傳 400
TC-07正常新增商品BodyPOST /api/items (合規 JSON Payload)201驗證成功建立資源並回傳 201 Created
TC-08負數價格防呆BodyPOST /api/items ("price": -100)400驗證防禦性檢查攔截負數價格

第 3/6 步： 建立並審查 run_tests.py

請在專案根目錄建立 run_tests.py，並確認 AI 生成的程式碼具備以下三個核心架構要素（若 AI 生成有缺失，可直接參考文末的 附錄參考程式碼 進行替換）：

  1. 測試矩陣完整性：陣列中是否包含 Step 1 定義的 8 項測試情境與正確的預期狀態碼（200 / 201 / 400 / 404）。
  2. 異常捕獲防呆：發送請求時是否有捕獲 urllib.error.HTTPError，確保遇到 400 或 404 時腳本不會崩潰中斷，能順利讀取 HTTP 狀態碼與錯誤訊息。
  3. 數據持久化：執行完畢後是否會將測試數據自動寫入 test_results.json。
