實驗 3（第三階段）：Vue 3 雙軌物聯網監控儀表板與 GitHub Pages 部署

Wayne Chang

發表於：2026年10月30日

更新於：2026年10月30日

這階段做一個 Vue 3 頁面。上半部直接訂閱實驗 1 的 MQTT，約每 5 秒更新一次溫溼度。下半部呼叫實驗 2 的 GET /api/sensor-logs，讀取已經寫進 Supabase 的紀錄。頁面本身不寫入資料庫。

學習目標

  1. 在 Vue 3（<script setup>）安裝瀏覽器端 mqtt，連線 wss://broker.emqx.io:8084/mqtt。
  2. 即時軌顯示溫度與溼度。數值達到 30°C 時，溫度卡片變紅。
  3. 歷史軌呼叫 GET /api/sensor-logs，用 computed() 計算這次讀到的列的平均溫溼度。
  4. 元件被拿掉時，在 onUnmounted 呼叫 mqttClient.end(true) 關掉 WebSocket。
  5. 用 GitHub Actions 把網站發布到 GitHub Pages，並用手機檢查兩條軌。

開始之前

  • 實驗 1 的 Pico 正在發布。Topic 是 vibe2026/iot/你的學號/telemetry。
  • 電腦上的 mqtt_bridge.py 正在跑。它的 API_ENDPOINT 是 https://實際部署網址/api/sensor-logs，路徑要留著。這支程式把 MQTT 寫進資料庫。
  • 這份頁面的 apiBaseUrl 只填 https://實際部署網址。不要貼橋接程式那條含 /api/sensor-logs 的網址，也不要填 http://127.0.0.1:5000（手機和 GitHub Pages 打不到）。
  • 即時卡直接向 Broker 訂閱，不經過橋接程式。同步按鈕只會再讀一次。橋接程式若還指著 127.0.0.1:5000，畫面上的歷史表不會出現新列。
  • 實驗 2 的 app.py 仍有 CORS(app)。GitHub Pages 才讀得到這支 API。
  • 這次另開 Vue 專案 vue-iot-dashboard，不要覆蓋課程原本的 Vue 作業。
  • 下面的學號先寫 B1130001。mqttTopic 和 deviceId 要分別改成你的學號，改其中一個不會改到另一個。兩者都要和實驗 1 的 DEVICE_ID 相同。

1. 實驗步驟

第 1/6 步： 建立 Vue 專案並安裝 mqtt

在終端機執行：

瀏覽器不能開埠 1883 的 TCP。mqtt 套件走 WebSocket。GitHub Pages 是 https://，頁面若再去連 ws://，瀏覽器會擋下混合內容。前端網址用 wss://broker.emqx.io:8084/mqtt。Pico 與橋接程式仍走 mqtt://broker.emqx.io:1883，訂的是同一個 Topic。

第 2/6 步： 用 C-I-C 提示詞產生草稿

打開 AI 程式助手，貼上以下提示詞。兩處 B1130001 改成你的學號。

這一步只產生草稿。下一步的 src/App.vue 才是要執行的版本。

生成後先不要執行。對照下一步，確認有這些項目：

  • 連線網址是 wss://broker.emqx.io:8084/mqtt。
  • Topic 是 vibe2026/iot/ 加上你的學號。
  • 歷史資料是 GET，查詢字串有 device_id。
  • onUnmounted 有 mqttClient.end(true)。

第 3/6 步： 貼上 src/App.vue

用下面這份取代 src/App.vue。學號有兩處，都要改：mqttTopic 裡的 B1130001，以及 deviceId。只改 Topic 時，歷史查詢仍用舊的 deviceId。apiBaseUrl 只填到網域，結尾不要斜線，也不要加上 /api/sensor-logs。本機 npm run dev 若要先打自己的 Flask，可暫時改成 http://127.0.0.1:5000。手機和 GitHub Pages 改回 Vercel 網域。

onUnmounted 什麼時候會跑

這份頁面的根元件是 App.vue。關掉分頁時，瀏覽器會自己斷掉 WebSocket，不一定會先跑 onUnmounted。這個鉤子是在元件被拿掉、頁面還開著時才會執行，例如之後把儀表板放進路由、離開該頁。程式仍要留著。

第 4/6 步： 本機先看兩條軌

Pico 維持發布。橋接程式維持執行，終端機要看得到 API HTTP 201。

打開終端機顯示的本機網址。

  1. 右上角變成 MQTT 已連線 (WSS)。Topic 是 vibe2026/iot/你的學號/telemetry。
  2. 即時卡片約每 5 秒變化一次。對 DHT11 哈氣後，先看接下來幾筆的溼度。溫度要達到 30°C，卡片才會變紅。教室本來就超過 30°C 時，第一筆到來就會是紅的。
  3. API 網址先填 Vercel 網域。按 同步歷史資料。表格出現的是橋接程式已經寫入的列。本機若改填 http://127.0.0.1:5000，只有這台電腦的開發頁打得到。

第 5/6 步： 設定 base、Actions，並發布到 GitHub Pages

編輯 vite.config.js。base 必須是儲存庫名稱，前後都有斜線。名稱設錯時，本機開發頁正常，Pages 會白畫面。儲存庫若就叫 帳號.github.io，base 改成 '/'。

新增 .github/workflows/deploy-pages.yml：

到 GitHub 儲存庫的 Settings → Pages → Build and deployment，Source 選 GitHub Actions。選單還沒有這個選項時，先完成下面的推送，再回到這頁選擇，並對失敗的那次 Action 按 Re-run。

Vite 專案的 .gitignore 已排除 node_modules。提交前執行 git status，清單裡不能有 node_modules。package.json 與 package-lock.json 要一起提交，Actions 的 npm ci 才裝得起來。

已經有遠端時，不要再執行 git init 與 git remote add，直接 git push。

Actions 出現綠色勾之後，網站在 https://你的帳號.github.io/vue-iot-dashboard/。

第 6/6 步： 用手機看已發布的網站

手機打開上一節的 Pages 網址。API 網址維持 Vercel 的 https 網域。

  1. 即時軌：燈號是 MQTT 已連線 (WSS)。哈氣後看接下來幾筆的溼度。溫度達到 30°C 時，溫度卡片變紅。
  2. 歷史軌：先看電腦上的橋接程式印出 API HTTP 201，再按手機上的 同步歷史資料。新列是橋接程式寫入後，這次 GET 才讀得到。

完成

2. 常見狀況

現象 處理方式
燈是綠的，溫度一直停在等待訊號 Topic 改成 vibe2026/iot/你的學號/telemetry，按重新訂閱。Pico 要仍在發布
即時卡有數字，表格沒有新列 橋接程式要在跑，而且已印出 API HTTP 201。同步按鈕只會 GET
本機表格有資料，手機沒有 手機的 API 網址改成 Vercel 的 https 網域，不要填 127.0.0.1，也不要含 /api/sensor-logs
Pages 打開是白畫面 vite.config.js 的 base 改成 /儲存庫名稱/，重新推送
Actions 在 npm ci 失敗 確認 package-lock.json 已提交
Settings 裡沒有 GitHub Actions 這個 Source 先推上 workflow，再選 Source，並 Re-run 失敗的那一次

3. 第三階段檢核表

  • 新專案是 vue-iot-dashboard，已安裝 mqtt，連線網址是 wss://broker.emqx.io:8084/mqtt。
  • Topic 與 device_id 都是你的學號。即時卡約每 5 秒更新。溫度達到 30°C 時卡片變紅。
  • 歷史表來自 GET /api/sensor-logs。橋接程式寫入之後，同步才看得到新列。
  • vite.config.js 的 base 是 /vue-iot-dashboard/。Pages 的 Source 是 GitHub Actions，該次 Action 為綠色。
  • 手機打開 https://你的帳號.github.io/vue-iot-dashboard/，即時軌與歷史軌都檢查過。
