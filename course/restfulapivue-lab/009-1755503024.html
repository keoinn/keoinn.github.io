實驗 9：個人記帳本｜從資料表到 Flask API

Wayne Chang

發表於：2026年11月7日

更新於：2026年11月7日

這份實驗把個人記帳本從資料表做到 Flask API。開始前先把既有的 Flask 骨架放到電腦上，再從步驟 0 請 AI agent 規劃資料表。驗收通過後，再依序做後面的實作。每一步的提示詞整段貼上，一次只做一步。提示詞後面的驗收都通過，再進下一步。

步驟 14 把請求與回應的格式定下來。步驟 15 把這支 API 部署到 Vercel。下一份用程式碼測試把這份格式跑過。通過之後，03-台股當日價格.md 記上市股票的當日價格，04-前端串接.md 用 HTML、CSS、JavaScript 做手機畫面。

這裡沒有可以直接執行的程式。資料庫語句與 Flask 程式都由 agent 依提示詞產出。

學習目標

  1. 從既有的 Flask 骨架接下去，不另起一個空專案。外層回應改成 code、message、data。
  2. 請 AI 依產品事實規劃資料表，再用 Alembic 遷移把表留在 Supabase 的 PostgreSQL。
  3. 帳戶、移轉、發票、入帳、花費、投資都做成 API。餘額與持有股數用查詢算出，不另存可手動改的欄位。
  4. 用 Postman 逐筆驗收。回傳的 data.id 寫進環境變數，下一步用 {{變數}}。
  5. 把同一支 API 部署到 Vercel。本機走 Session pooler，線上走 Transaction pooler。

開始之前

實作從既有專案接下去，不另起一個空的 Flask 專案：https://github.com/[替換成自己的GithubID]/flask-vibe-api。產生任何文件之前，先把它放到 ./ledger-api。步驟 0 才把設計說明寫進 docs。步驟 1 再改 app.py。

留下的是檔案、已釘選的 Flask 3.1.3、app.json.ensure_ascii = False、JSON 錯誤處理、127.0.0.1:5000、.gitignore 與 vercel.json。那個專案的外層鍵是 status（success / error），健康檢查的 data 是 running 與 timestamp，任務放在記憶體清單。從步驟 1 起，外層改成這份的 code、message、data，記憶體任務拿掉。後面的測試、報價與畫面都接這個改過的專案。

技術選擇固定如下，後面每個提示詞都沿用：

  • PostgreSQL 用 Supabase 上的那一座。結構用遷移留下版本，不靠在表格編輯器裡點出來的表。
  • Flask 沿用該專案已釘選的 3.1.3，透過 SQLAlchemy 連線，遷移工具用 Alembic。之後只追加套件，不把已釘選的版本改松。
  • db 放在 extensions.py，用尚未綁定的 SQLAlchemy() 建立。app.py 提供 create_app()，裡面呼叫 db.init_app(app)，檔案最外層仍是 app = create_app()。模型放在 models.py，只從 extensions 取 db。
  • 專案根目錄是 ./ledger-api。虛擬環境在 ./.venv。
  • 連線字串只放環境變數 DATABASE_URL。版本庫裡只留變數名稱，不留密碼與金鑰。
  • 回應封裝是 code、message、data。code 與 HTTP 狀態碼用同一個數字。message 寫人話。資料庫的原始錯誤留在伺服器。

先前對過競品後補進設計的四件事也在這份裡：帳戶與移轉、發票明細、投資交易種類、每筆外幣的台幣匯率。預算、固定收支、載具自動匯入、銀行同步先不做。這 14 步也不建股價表；上市股票的當日價格留到 03-台股當日價格.md。

有路由的步驟用 Postman 驗收。請求正文就是該步的測試資料。201 回傳的 data.id 存進環境變數，下一步用 {{變數}}，不要手打 id。

資料長什麼樣子

一個人用。錢落在帳戶上。入帳與花費是生活裡的進出。移轉是帳戶之間換地方。發票是單據，可以拆成多筆花費。投資是標的與交易，持有股數由交易算出，不另存一個可手動改的庫存。

表在記什麼
accounts現金、銀行、信用卡、券商交割戶
transfers從一個帳戶轉到另一個帳戶
invoices一張統一發票
invoice_items發票上的品項
draw_periods一期開獎
draw_prizes該期某一個獎的號碼與獎金
income_categories入帳分類
incomes一筆入帳
expense_categories花費分類
expenses一筆花費
instruments一檔標的
trades一筆投資交易

關係：

  • 入帳、花費、移轉、投資交易都指向一個帳戶。帳戶底下還有這些列時，帳戶不能刪。
  • 一筆花費可以指向一張發票。一張發票可以對到多筆花費。發票仍被花費參照時不能刪。
  • 發票品項跟著發票。發票在，品項才在。
  • 中獎入帳時，incomes.invoice_id 指向那張發票，一張發票最多產生一筆入帳。
  • 現金股利入帳時，incomes.trade_id 指向那筆交易，一筆交易最多產生一筆入帳。
  • 餘額不另存欄位。由開帳金額，加上入帳、賣出實收、股利現金，減去花費、買進成本，再計入移轉。用查詢算出。

金額用可以有小數的數字，幣別用三碼。台幣的匯率記 1。時間用 timestamptz，存 UTC。created_at 由資料庫在插入時填。updated_at 在更新時由程式寫入。

程式知道資料庫在哪裡，並用 GET /api/health/db 確認連得上。還沒有業務表。已經套用的遷移以後不回頭改，要改就新增下一版。

先取得連線字串

這一支開始之前，先在自己的 Supabase 專案取出資料庫連線字串，寫進 ./ledger-api/.env。提示詞不要代做這件事，字串也不要貼進對話或版本庫。

  1. 打開該專案。免費專案若處在暫停，先恢復，否則後面的連線會一直等。
  2. 進入 Connect，選擇 URI。這條是給 SQLAlchemy 與 Alembic 用的資料庫連線，密碼是資料庫密碼。可公開金鑰與秘密金鑰是另一組，不放進這條字串。
  3. 在 Connect 選 Session pooler，複製連接埠 5432 的 URI。主機名稱含 pooler.supabase.com，使用者是 postgres. 後面加上專案 ref。這條走 IPv4，而且一條連線會留到工作階段結束，遷移與稍後的測試 schema 才保得住 search_path。
  4. 不要選主機為 db.<專案ref>.supabase.co 的直連。免費專案的直連只有 IPv6。家用網路若只有 IPv4，GET /api/health/db 會回 500，伺服器日誌是 failed to resolve host，看起來像找不到主機。
  5. 不要選 Transaction pooler。那一條是連接埠 6543，留到步驟 15 給 Vercel。本機、遷移與測試都不用它。
  6. 密碼若沒留下，到 Database Settings 重設資料庫密碼，再回到 Connect 複製新的 URI。密碼裡若有 @、:、/ 這類字元，放進 URI 時要先做 URL 編碼。
  7. ./ledger-api/.env 寫成一行，形如 DATABASE_URL=postgresql://postgres.專案ref:密碼@aws-0-區域.pooler.supabase.com:5432/postgres。區域那一段以 Connect 畫面上的為準，不要自己拼。檔案留在本機。.env.example 只保留 DATABASE_URL=，等號右邊空著。改完連線字串要重啟 Flask，舊程序還握著上一條網址。

步驟 3：帳戶與移轉的表

帳戶是錢所在的地方。移轉只換帳戶，不計入入帳，也不計入花費。信用卡留結帳日與繳款日，兩個都可以空。

accounts：name 必填且不重複。kind 只允許 cash、bank、credit_card、broker。currency 三碼必填，預設 TWD。opening_balance 必填，可以是 0，也可以是負數（信用卡）。statement_day、payment_day 可空，有值時是 1 到 31。主鍵用資料庫產生的整數，建立後不改。

transfers：transferred_on、amount、from_account_id、to_account_id、currency、fx_rate_to_twd 必填。amount 與匯率都要大於 0。轉出與轉入不能是同一個帳戶。兩個外鍵都指向 accounts，帳戶還被移轉參照時不能刪。note 可空。

兩張表都有 created_at、updated_at。

模型不要跟 app 互相匯入

這一支會第一次出現 models.py。app.py 若在載入模型，模型又回頭 from app import db，Python 會在 Account 還沒定義完時停下，錯誤是 ImportError: cannot import name 'Account' from 'models'。括號裡建議把 ./ledger-api/models.py 改名，那是循環匯入時附上的提示。改檔名之後，應用程式與模型仍會互相等待。

這裡用 Flask 的 application factory。db 先放在 extensions.py，create_app() 裡再 db.init_app(app)。模型只向 extensions 拿 db。app.py 最外層仍然要有 app = create_app()，本機與 Vercel 才找得到這個實例。

步驟 12：投資的 API

賣出前先依時間算出當時還有的數量。作廢的交易不計入。計算順序按 traded_on，同一天再按 id：

  • buy：數量增加。數量與價格必填且大於 0。
  • sell：數量減少。減完不得小於 0，否則拒絕這筆賣出。
  • stock_dividend：數量增加，價格為 0。
  • drip：數量增加，同時有一筆再投入的現金金額。
  • split 與 merge：當時股數乘上 ratio。ratio 必填且大於 0。
  • capital_reduction：數量減少，可帶 cash_amount。
  • cash_dividend：股數不變，cash_amount 必填且大於 0。

買進從帳戶扣掉（價格乘數量，加手續費與交易稅）乘匯率。賣出把實收（價格乘數量，減手續費與交易稅）乘匯率加回帳戶。現金股利與減資退回的現金也加回帳戶。這些都在餘額查詢裡計算，不寫進餘額欄位。

若請求要同時入帳，現金股利或減資現金要在同一筆交易裡寫進 trades 與 incomes，incomes.trade_id 指向剛寫入的交易。

步驟 14：定義交換格式

步驟 1 到 13 各自描述了欄位。前端要有一份對得起來的格式：每個請求送哪些欄位、每個回應的 data 長什麼樣子、失敗時客戶端看哪一句人話、伺服器留下哪些內部錯誤。這一支不改路由、不改資料表，只把格式寫成 ./ledger-api/docs/交換格式.md。

共通規則

每一筆回應都是這三個鍵，不多不少。code 與 HTTP 狀態碼相同。message 是人話。成功時 data 放結果；失敗時 data 是 null。

情況HTTP 與 codedata
查詢成功，含空清單200物件或陣列
新增成功201資料庫寫入後的那一列
更新成功、餘額、持有、對獎、月合計200該端點約定的物件
格式不對、約束沒過400null
指定的 id 不存在404null
資料庫連不上500null

客戶端不送 id、created_at、updated_at。送了也不採用。日期用 YYYY-MM-DD。created_at 與 updated_at 用 UTC 的 ISO 8601。金額、匯率、股數是 JSON 數字。幣別是三碼字串。可空欄位在回應裡仍出現，值為 null。請求可以省略可空欄位。

回應裡的物件

帳戶：id、name、kind、currency、opening_balance、statement_day、payment_day、created_at、updated_at。kind 只會是 cash、bank、credit_card、broker。

餘額：

移轉：id、transferred_on、amount、currency、fx_rate_to_twd、from_account_id、to_account_id、note、created_at、updated_at。

分類（入帳與花費同一形狀）：id、name、description、created_at、updated_at。

入帳：id、received_on、amount、currency、fx_rate_to_twd、category_id、account_id、source、note、invoice_id、trade_id、created_at、updated_at。

花費：id、spent_on、settled_on、amount、currency、fx_rate_to_twd、category_id、account_id、merchant、note、invoice_id、created_at、updated_at。

發票清單裡的一列：id、number、issued_on、amount、kind、currency、fx_rate_to_twd、random_code、seller_name、seller_ban、prize_status、created_at、updated_at。kind 是 paper 或 electronic。prize_status 是 unchecked、lost、won、claimed、void。

單筆發票在上述欄位之外再加 items 與 expense_ids。品項是 id、invoice_id、name、quantity、unit_price、line_amount、created_at、updated_at。

開獎期別：id、period_key、created_at、updated_at。獎項：id、draw_period_id、tier、matching_number、amount、created_at、updated_at。

對獎結果：

中獎入帳回傳新建的入帳物件，invoice_id 有值。發票的 prize_status 改由之後的單筆查詢看到，是 claimed。

標的：id、market、symbol、name、currency、created_at、updated_at。market 是 tw_stock、us_stock、fund、other。

持有：

交易：id、instrument_id、account_id、trade_type、traded_on、quantity、price、fee、tax、cash_amount、ratio、currency、fx_rate_to_twd、voided_at、created_at、updated_at。trade_type 是 buy、sell、cash_dividend、stock_dividend、drip、split、merge、capital_reduction。

月合計：

健康檢查的 data 維持 status 與 time。這裡的 status 只放在 data 裡面，外層仍是 code。

內部錯誤

給客戶端的失敗回應仍只有 code、message、data。data 是 null。message 用下表的固定句子。表名、約束名、SQL、例外型別、堆疊不進 JSON。

伺服器另外寫一筆日誌，只留在主機上。欄位如下。

鍵內容
timeUTC，ISO 8601
request_id這一筆請求的識別碼，伺服器產生
methodHTTP 方法
path路徑，不含查詢字串裡的機密
http_code回給客戶端的狀態碼
error_code下表的內部代碼
exception_type例外類別名稱，沒有例外可為 null
sqlstatePostgreSQL 的 SQLSTATE，不是資料庫錯誤則為 null
constraint_name約束名稱，沒有則為 null
table_name表名，沒有則為 null
detail資料庫或程式的原始說明

同一種失敗，客戶端永遠看到同一句 message，日誌用 error_code 區分原因。

error_codeHTTP客戶端 message

rule.empty_text 在入帳端點的句子是「來源與備註至少填一個」，在花費端點是「商家與備註至少填一個」。金額不大於 0、匯率不大於 0、日期格式錯誤、種類不在允許清單，都歸 request.bad_value，句子用「欄位的值不合法」。

步驟 15：部署到 Vercel

表已經在 Supabase。線上的程式只負責讀寫，不在 Vercel 上跑遷移。本機 .env 維持 Session pooler、連接埠 5432，主機名稱含 pooler.supabase.com。Vercel 的 DATABASE_URL 用 Transaction pooler，連接埠 6543。兩邊是同一座專案、同一組資料庫密碼。

vercel.json 目前只有 $schema。這一支補上 app.py 的 maxDuration，不加入把路徑轉去別的檔案的 rewrite。Vercel 會自己找到名為 app 的 Flask 實例。

先放上環境變數

  1. git status 裡不要出現 .env。出現就先停下，確認 .gitignore 有把它排除。
  2. 倉庫根目錄要直接看得到 app.py 與 requirements.txt。若 Git 倉庫是整份講義、程式在 ledger-api 底下，到 Vercel 把 Root Directory 設成 ledger-api。
  3. 把這個目錄推上 GitHub，再在 Vercel 匯入。平台認得出 Flask 與 requirements.txt。
  4. Supabase 的 Connect 選 Transaction pooler，複製連接埠 6543 的 URI。使用者名稱通常是 postgres. 後面加上專案 ref。密碼規則與步驟 2 相同。
  5. Vercel 的 Settings → Environment Variables 新增 DATABASE_URL，值貼上那條 URI，不加引號。
  6. 存檔後按 Redeploy。沒有重新部署的那一次，線上仍用舊的環境。

完成

做完時對得上這些事：

  • 健康檢查回 200，中文 message 不會變成萬國碼。

  • 新增回 201，回應裡的 id 與 created_at 是資料庫寫入的值。
  • 轉帳不會出現在入帳合計或花費合計。
  • 一張發票可以掛兩筆花費。中獎入帳失敗時，發票不會停在已領。
